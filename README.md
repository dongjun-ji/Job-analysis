## 왜 만들었나

AI 도구로 IT 산업 트렌드를 분석하다 보니, 이걸 취업에도 써먹을 수 있겠다는 생각이 들었다. 채용공고만큼 지금 업계가 어떤 사람을 찾는지 솔직하게 보여 주는 자료도 없으니까.

마침 이직 준비를 하면서 아침마다 채용 사이트를 도는 데 하루 1~2시간씩 쓰고 있었다. 공고를 고르는 기준은 매일 똑같았다. 희망 직무인지, 근무지가 서울이나 분당인지, 경력 요건이 3년 이하인지. 시간을 제일 많이 잡아먹은 건 그다음이었다. 직무명이 같아도 실제로 하는 일은 공고마다 달라서, 결국 원문을 하나씩 열어 내 경험과 맞춰 봐야 했다.

그래서 이 일을 AI한테 넘기고, 컨설턴트가 말한 GitHub Actions로 매일 알아서 돌아가게 만들었다. 리포트에 매일 "공통 요구 역량"이 같이 나오는 것도 처음 출발점이 트렌드 분석이었기 때문이다.

## 어떻게 돌아가나

매일 08:52에 Claude 예약 작업이 돈다. 저장소에 있는 기준 문서(`config/prompt.md`)와 프로필을 읽고, 웹에서 공고를 찾아 원문까지 열어 본 다음, 결과를 `data/reports/날짜.json`으로 올린다. 이 파일이 올라오면 GitHub Actions가 받아서 형식을 검사하고 HTML을 만들어 GitHub Pages에 올린다.

```
Claude 예약 작업 (매일 08:52)
  기준 문서·프로필·최근 추천 기록 읽기 → 공고 검색 → 원문 확인 → 점수 작성
  └─ data/reports/YYYY-MM-DD.json 커밋
        ↓ push가 들어오면 자동 실행
GitHub Actions
  형식 검사 → 합계·D-day·재추천 계산 → HTML 생성 → data/history.json 갱신 → Pages 배포
```

AI한테는 판단만 맡겼다. 공고 요건과 내 경험이 얼마나 맞는지는 AI가 보고, 점수 합계나 마감까지 남은 날짜처럼 답이 정해진 계산은 코드가 한다. 그래서 AI는 항목별 점수만 쓰고 합계는 쓰지 않는다. 40점 만점 항목에 55점이 들어오면 빌드가 멈추고, 페이지는 어제 것이 그대로 남는다.

## 처음엔 이렇게 안 만들었다

첫 버전은 GitHub Actions가 Claude API를 직접 부르는 구조였다. 다 만들고 나서야 내가 쓰는 Pro 구독에는 API가 포함돼 있지 않다는 걸 알았다. 매일 돌리면 토큰 비용에 웹 검색 비용(1,000회당 $10)까지 따로 나간다. 그래서 역할을 바꿨다. 분석은 구독 안에서 도는 예약 작업이 하고, Actions는 검사와 배포만 한다. 지금은 구독료 말고 따로 나가는 돈이 없다.

공고를 어디서 가져올지도 한참 고민했다. 채용 사이트를 통째로 긁어 오면 편하지만, 잡코리아가 사람인의 크롤링을 문제 삼아 이긴 판례가 있다. 공개 저장소에 올릴 프로젝트에서 굳이 그 길로 갈 이유가 없었다. 그래서 AI가 검색으로 후보를 찾고 공고를 하나씩 열어 보게 했고, 페이지에는 공고 본문 대신 회사명과 링크, 평가만 올린다.

첫 배포 날엔 커밋 옆에 빨간 X가 떴다. 추천 기록 파일은 첫 리포트가 나와야 생기는데, 아직 없는 파일을 저장하려다 멈춘 거였다. 로그에서 실패한 단계를 찾아 고쳤다. 그냥 뒀으면 첫 데이터가 들어온 날 페이지가 안 바뀌었을 거다.

그런데 정작 첫 실제 운영 날(11월 20일) 아침에는 다른 데서 막혔다. 리포트는 만들어졌는데 페이지가 그대로였다. 예약 작업이 저장소에 올리려다 권한 없음(403)으로 거절당한 거였다. 이상한 건 전날 테스트에서는 똑같은 업로드가 잘 됐다는 점이다. 두 작업의 차이는 두 가지였다. 하나는 만든 시점(저장소 연결 전이냐 후냐), 다른 하나는 실행 방식(수동이냐 자동이냐)이었다.

어느 쪽인지 모르는 채로 고치면 다음 날 또 같은 일이 생길 수 있었다. 그래서 바로 손대지 않고, 저장소를 연결한 뒤에 만든 테스트 작업을 3분 뒤 자동으로 돌게 걸어 뒀다. 30초 만에 올라갔다. 자동 실행이 문제가 아니라, 매일 도는 작업을 저장소 연결 전에 만들어 둔 게 원인이었다. 작업을 새로 만들어 바꿨고, 그날 리포트는 이미 만들어진 JSON을 직접 올려서 살렸다.

운영 나흘째에는 1위가 나흘 내내 같은 공고, 같은 79점이라는 게 눈에 들어왔다. 이미 이력서를 쓰고 있는 곳이라 매일 맨 위에 뜰 이유가 없었다. 처음엔 그 회사를 통째로 빼려고 했는데, 그러면 같은 회사에서 더 맞는 공고가 새로 올라와도 못 보게 된다. 그래서 지원한 공고만 하나씩 빼고, 1위에는 최근 7일 안에 추천하지 않은 새 공고를 두게 바꿨다. 개수를 채우다 40점대가 섞이는 것도 보여서 50점 미만은 아예 빼기로 했다. 어디에 지원했는지는 공개할 이유가 없어서, 제외할 공고 목록은 저장소가 아니라 예약 작업 설정에만 둔다.

## 점수는 이렇게 매긴다

100점 중 직무 경험 40, 필수 자격 30, 산업·도메인 20, 근무 조건 10이다. 직무명이 같다는 이유만으로는 점수를 주지 않는다. 매일 5~6개를 추천하고 그중 상위 3곳만 지원 전략까지 정리한다. 합계 50점 미만은 AI가 넣더라도 코드가 화면에서 뺀다. 마감됐거나 계약직이거나 경력 차이가 큰 공고는 빼고, 왜 뺐는지는 리포트 맨 아래에 남긴다. 확인 못 한 정보는 지어내지 않고 "확인 필요"로 둔다.

## 공개 범위

저장소와 리포트는 공개지만 검색엔진에는 안 걸리게 해 뒀다. 공고마다 내가 부족한 점이나 자기소개 문장은 페이지에 올리지 않고 아침 알림으로만 받는다.

## 화면만 보고 싶다면

```bash
pip install -r requirements.txt
python scripts/generate_report.py --sample   # 예시 데이터로 docs/index.html 생성
```

## 파일 구성

```
.github/workflows/daily-report.yml  데이터가 올라오면 검사·빌드·배포
scripts/generate_report.py           검사 → 계산 → HTML 생성 → 기록
config/prompt.md                     검색 조건과 평가 기준 (AI가 읽는 문서)
config/profile.md                    프로필
templates/report.html                리포트 디자인
data/reports/                        날짜별 분석 결과
data/history.json                    날짜별 추천 기록
docs/                                GitHub Pages로 공개되는 리포트
```
