# 데일리 채용 분석 지침

이 문서는 매일 아침 Claude 예약 작업이 읽고 따르는 분석 기준이다. 판단 기준을 코드 밖 문서로 분리해, 기준을 바꿀 때 이 파일만 고치면 되게 했다.

## 입력
- 지원자 프로필: `config/profile.md`
- 최근 추천 기록: `data/history.json` (최근 7일 안에 추천한 공고는 가급적 제외)

## 검색 조건
1. 웹 검색을 직무·플랫폼별로 나눠 수행한다. 예: "원티드 사업운영 서울", "사람인 운영매니저 신입 경력", "잡코리아 사업기획 3년 이하", "점핏 서비스운영", "링크드인 전략기획 주니어 서울", 기업 공식 채용 페이지(greetinghr, ninehire 등).
2. 최근 7일 안에 등록되거나 업데이트된 공고를 우선한다.
3. 후보 공고는 원문 페이지를 직접 열어 직무, 자격요건, 근무지, 고용형태, 마감 여부를 확인한다. 원문을 열 수 없으면 제외한다.
4. 마감된 공고, 중복 공고, 계약직·인턴, 서울·분당(성남) 외 근무지는 제외한다.
5. 명시된 경력 요건이 지원자와 크게 다르면 제외한다(예: 5년 이상, 팀장급, 특정 산업 실무 필수).
6. 적합한 공고가 5개 미만이면 억지로 채우지 않는다. 최대 10개.
7. 확인하지 못한 정보는 추측하지 말고 "확인 필요"라고 쓴다.
8. 최근 추천 기록에 있는 공고를 다시 넣어도 되지만(예: 마감 임박), 새 공고를 우선한다. 재추천 표시는 코드가 붙인다.

## 평가 기준
- 직무명만 보고 추천하지 않는다. 실제 업무 내용과 자격요건을 프로필의 구체적 경험과 대조한다.
- 적합도(100점) = 직무 경험 일치도(40) + 필수 자격 충족도(30) + 산업·도메인 적합도(20) + 근무 조건 적합도(10). 항목별 점수만 쓰고 합계는 쓰지 않는다(코드가 계산).
- 근거 없는 긍정 평가는 하지 않는다. 합격 가능성을 떨어뜨리는 요인을 솔직하게 쓴다.
- 프로필에 없는 경험은 절대 지어내지 않는다.

## 공개 범위
이 JSON과 리포트 페이지는 공개된다. 공고별 부족한 점, 지원 전 보완할 점, 자기소개 문장처럼 지원자 개인의 약점이나 지원 전략이 드러나는 내용은 JSON에 넣지 않는다. 이런 내용은 예약 작업이 사용자에게 보내는 비공개 알림 메시지에만 쓴다.
